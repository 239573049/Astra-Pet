# 02 需求与亲密度

## 1. 基调【待定 L1，推荐 A：纯陪伴】

| 方案 | 做法 | 好处 | 问题 |
|---|---|---|---|
| **A. 纯陪伴** | 数值只影响表现：饿了会摸肚子、冒「饿」的小气泡，困了打哈欠、走得慢。不生病、不死亡、不离家出走，亲密度等级不会掉 | 不制造负担，忙的时候不用管它；符合「工作时的伙伴」定位 | 对喜欢养成的用户刺激不够 |
| B. 养成 | 长期不喂会生病（需要「治疗」）、亲密度下降、甚至跑掉 | 有养成的紧张感 | 用户休假一周回来发现宠物病了 / 跑了，体验很差；需要更多素材（生病、治疗） |
| C. A 默认 + 「认真养」开关 | 开关打开后衰减更快、低数值有更强的后果 | 两类用户都照顾 | 两套平衡要调；先把 A 做好再说 |

下面的数值都按 A 设计。

## 2. 有哪些数值

| 数值 | 范围 | 性质 | 一句话 |
|---|---|---|---|
| **饱腹** `satiety` | 0～100 | 短期需求，随时间降，喂食升 | 饿不饿 |
| **精力** `energy` | 0～100 | 短期需求，活动和清醒时降，睡觉 / 省电时升，夜里降得快 | 困不困 |
| **心情** `mood` | −100～100 | 短期状态，被互动拉高，被冷落 / 饿 / 困 / 摔疼拉低，自动回到基线 | 开不开心 |
| **亲密度** `bond` | 经验值 → 等级 1～10 | 长期，只涨不掉（A 方案） | 和你多熟 |

**【待定 L12】不做清洁 / 洗澡（推荐）。** 多一个需求就要多一套「变脏」的表现（叠加图层或专门片段）和「洗澡」的动作，
做一只宠物的成本又涨一截；喂食和睡觉已经足够撑起「照顾它」的感觉。

## 3. 变化规则

### 3.1 每分钟的模拟

`PetLife.Tick` 每分钟跑一次（用 `TimeProvider`，测试里可以拨快），以「每小时」为单位描述速率：

| 数值 | 自然变化（清醒） | 自然变化（睡觉 / 省电 / 暂停） | 特质影响 |
|---|---|---|---|
| 饱腹 | −6 / 小时（满到饿约 12 小时） | −2 / 小时 | `greedy` 倍率 |
| 精力 | −5 / 小时；22:00～6:00 额外 −5 | +25 / 小时 | `energetic` 倍率（消耗） |
| 心情 | 向基线回归：每小时缩小与基线差距的 30% | 同左 | — |
| 心情基线 | `10 + 饱腹修正 + 精力修正 + 冷落修正` | | `clingy` 放大冷落修正 |

- **饱腹修正**：饱腹 < 30 时 −20，< 10 时 −40。**精力修正**：精力 < 20 时 −15。
- **冷落修正**：最近一次「主动互动」（单击、摸头、喂食、对话、逗玩）距今超过 2 小时开始 −5 / 小时，封顶 −30；有互动立即清零。
  用户在电脑前（空闲检测说有键鼠活动）但不理它，和用户根本不在，是两回事：**用户不在电脑前不算冷落**（平台不支持空闲检测时一律不算）。
- 所有速率乘全局「变化速度」（控制台：慢 0.5× / 标准 1× / 快 2×）。

### 3.2 互动带来的变化

| 互动 | 饱腹 | 精力 | 心情 | 亲密度经验 | 冷却 / 上限 |
|---|---|---|---|---|---|
| 单击 | | | +2 | +1 | 每分钟最多算 3 次 |
| 摸头 | | | +6 | +3 | 30 秒 |
| 喂食（普通） | +25 × 食量 | +3 | +8（喜欢 ×1.5，讨厌 −10） | +5 | 饱腹 ≥ 95 时拒绝（播摇头 / `confused`，说「吃不下啦」） |
| 对话一轮 | | | +3 | +4 | 每天前 20 轮计经验 |
| 逗它玩（03 §4） | −3 | −8 | +12 | +6 | 一次玩 1 分钟算一轮 |
| 陪伴专注（番茄钟完成一轮） | | | +5 | +8 | 不限（专注本身就是限流） |
| 被甩（轻） | | | `bold` 高 +5 / 低 −5 | | |
| 被甩（重，撞墙 / 高处摔） | | | `bold` 高 0 / 低 −12 | | |
| 连点（1 秒内 ≥ 6 下） | | | −8 | | 播 `angry` / 晕 |
| 吵醒（睡觉时单击） | | +0 | −6 | | 有 `sleep` 时才会发生 |

- **每日亲密度上限 60 经验**（各项加起来），超出部分不计。防止挂个连点器刷满，也让「每天来看看它」比「一天猛刷」更有意义。
- 数字都放在 `LifeTuning`（Core 里的一个常量表），测试和调平衡都改一处；不开放给角色包改（避免第三方包把数值调得很离谱）。

### 3.3 阈值与事件

数值 **穿过** 阈值时发一次事件（不是低于阈值期间一直发）。带回差，避免在阈值附近抖动反复触发：

| 事件 | 条件 | 默认规则（06 §3） |
|---|---|---|
| `needs.hungry` | 饱腹从 ≥ 30 降到 < 30 | 播 `hungry`（回退 `sad` → `idle`），冒食物图标气泡，台词「有点饿了…」；**不朗读、不弹通知** |
| `needs.starving` | 饱腹 < 10 | 同上，30 分钟最多一次 |
| `needs.fed` | 饱腹从 < 30 回到 ≥ 40 | 播 `happy` |
| `needs.sleepy` | 精力 < 20 | 播 `yawn`（回退 `stretch` → `idle`）；夜里进入睡觉姿态（04 §3，有 `sleep` 时） |
| `needs.rested` | 精力回到 ≥ 60 | 睡着的醒来（`exit` 段） |
| `mood.changed` | 心情档位变化（低落 < −30 / 平常 / 开心 > 40） | 默认无规则；给用户自己绑 |
| `bond.levelUp` | 亲密度升级 | 播 `celebrate`，冒等级气泡和这一级的解锁台词 |

饿和困 **只会做动作和冒小气泡**，不会弹系统通知、不会朗读、不会打断用户触发的动作（规则优先级 `ambient`→ 只在空闲时生效，见 06 §3）。

## 4. 关掉程序的时间【待定 L2，推荐 B】

| 方案 | 做法 | 问题 |
|---|---|---|
| A. 冻结 | 退出时存档，下次打开原样恢复 | 简单；但「一周没开，打开它还是饱的」不像活物 |
| **B. 按真实时间衰减 + 下限保护** | 打开时按离线时长补算，但离线期间饱腹最低降到 35、精力回满、心情回基线；离线超过 1 天，打开时播 `greet` 并说「好久不见」 | 回来时它「有点饿」，正好给用户一个喂它的理由，又不会饿坏 |
| C. 衰减无保护 | 照常补算 | 每次周末回来都是饿扁的，等于惩罚用户休息 |

补算不逐分钟模拟，直接用闭式：饱腹 `max(35, s − 2 × 小时)`（离线按睡眠速率算），精力 100，心情 = 基线。
系统时间被往回调（离线时长为负）时按 0 处理；离线时长超过 365 天按 365 天。

## 5. 亲密度等级与解锁

| 等级 | 累计经验 | 称呼（默认，包可以改） | 解锁 |
|---|---|---|---|
| 1 | 0 | 初次见面 | — |
| 2 | 60 | 认识了 | 单击台词扩充 |
| 3 | 180 | 熟悉 | 主动靠近光标（`clingy` 决定频率） |
| 4 | 400 | 朋友 | 动作 `unlock.bond ≤ 4` 的动作进随机链 |
| 5 | 700 | 好朋友 | 会叫用户的称呼（设置里填的） |
| 6 | 1100 | 亲近 | |
| 7 | 1600 | 很亲近 | |
| 8 | 2200 | 挚友 | |
| 9 | 3000 | 家人 | |
| 10 | 4000 | 最重要的人 | 专属台词 |

- 按每日上限 60，最快约 2 个多月满级；正常使用（每天 20～30）半年左右。
- **解锁是包定义的**：动作可以带 `"unlock": { "bond": 4 }`，没到等级前不进随机链、不给 Agent 选，控制台里显示锁和「亲密度 4 解锁」；
  台词可以按等级分组（`lines` 支持 `{ "bond": 5, "text": "…" }` 形式，06 §3.2）。内置角色的解锁内容由我们写。
- 亲密度等级和称呼写进系统提示词的情境层（「你和用户认识 23 天了，是好朋友（亲密度 5）」），LLM 的语气跟着变近。
- **A 方案下等级不掉。** 长期不来只是「好久不见」的问候，不扣经验。

## 6. 数值跟着谁【待定 L3，推荐 A】

每只宠物各一份（按 `petKey`，和动作覆盖层同目录）。换宠物时原来那只的状态冻结（按「离线」处理，下次换回来时补算）。
全局一份（B）的问题是亲密度天然属于某只宠物：和小t 熟了，换成大肥鱼也是「好朋友」很奇怪。

## 7. 开关和调节

控制台「宠物 → 状态」页（06 §5）：

- **启用宠物体系**（默认开；关掉后数值冻结、不发需求事件、情境层不写，回到 0.1.x 的纯观赏）
- **变化速度**：慢 / 标准 / 快
- **饿了 / 困了时提醒我**：冒气泡（默认）/ 只在状态浮层显示 / 不提醒
- **重置这只宠物的状态**（二次确认；只清数值和累计，不清动作覆盖和记忆）
