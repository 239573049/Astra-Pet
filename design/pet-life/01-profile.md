# 01 宠物档案

## 1. 档案分几块

现在 `pet.json` 里和「这只宠物是什么样的」有关的只有 `persona`（给 LLM 的文本）和 `render`（画布常量）。
新增一个 `profile`，放程序要读的结构化参数：

| 块 | 内容 | 谁用 | 来源 |
|---|---|---|---|
| `persona`（已有） | 名字、身份、性格、说话方式、喜好、口头禅、问候语 | 系统提示词 | 作者填 / 工作台 ① |
| `profile.traits` | 性格数值：活泼、黏人、贪吃、胆量、好奇 | 随机链调制、需求变化速度、互动反应 | 作者填 / 工作台 ① 滑块 |
| `profile.body` | 身体包围盒、头 / 身 / 脚的分界、贴墙接触点 | 点击分区、落地对齐、爬墙对齐、命中测试 | 工作台自动测量（05 §4），作者可改 |
| `profile.physics` | 体重、弹性、爬速、走速倍率、怕不怕摔 | 抛掷 / 下落 / 爬墙（04） | 作者填，有默认值 |
| `profile.diet` | 喜欢 / 讨厌的食物、食量 | 喂食（03 §2） | 作者填 / 工作台 ① |
| `profile.species` | 物种大类：`humanoid` / `quadruped` / `flying` / `blob` / `other` | 选默认物理参数和工作台模板措辞 | 作者选 |

全部可选。缺了用默认值，老包（格式 1、没有 `profile` 的格式 2）行为和现在一样。

## 2. 性格数值【待定 L10，推荐 B】

五个特质，0～100，默认 50。刻意少：每个都要能落到具体的程序行为上，落不下去的就留给 `persona` 文本。

| 特质 | 高的时候 | 低的时候 | 程序里影响什么 |
|---|---|---|---|
| `energetic` 活泼 | 爱走动、爱爬、动作多 | 爱发呆、待机多 | 随机链里 move / climb / 情绪动作的倍率；精力消耗速度 |
| `clingy` 黏人 | 被冷落时心情掉得快，主动凑近光标 | 独立，不太在意 | 「被冷落」的心情衰减；主动靠近光标的概率；亲密度获取倍率 |
| `greedy` 贪吃 | 饿得快，吃到喜欢的东西特别开心 | 饿得慢 | 饱腹衰减速度；喂食的心情加成 |
| `bold` 胆量 | 被甩出去觉得好玩 | 被甩会害怕、生气 | 抛掷 / 摔落后的反应角色（`happy` vs `surprised` / `angry`）；敢不敢爬高 |
| `curious` 好奇 | 光标经过时看过去，爱探索屏幕边缘 | 不理光标 | 视线跟随的概率；走路时选择去屏幕边 / 爬墙的概率 |

- 特质只调「概率和倍率」，不开关能力。比如 `bold=0` 的宠物被甩照样会飞出去，只是落地后播 `surprised` 而不是 `happy`。
- 倍率统一用 `lerp(0.5, 1.5, trait/100)`，即特质从 0 到 100 对应 0.5× 到 1.5×，避免极端值让某个行为完全消失或刷屏。
- 写进系统提示词的情境层时转成文字（「你很贪吃、胆子有点小」），和 `persona.personality` 一起给 LLM。
- 用户可以在控制台覆盖（覆盖层，和动作一样按 `petKey` 存），「恢复默认」回到包里的值。

**方案对比（L10）：** 只用人设文本（A）最简单，但「贪吃」只能影响 LLM 说什么，程序里的饥饿速度、反应都没法跟着变，
同一只宠物在对话里很贪吃、桌面上和别的宠物一模一样。B 让性格既影响说话也影响行为。

## 3. 身体与接触点

现在的常量（`ClickZones`：头顶 y≈60、脚底 y≈330；`render.bodyHeight=270`、`feetY=330`）是小t 的经验值，工作台合成首尾帧时也按这个对齐。
换成按包读取：

```jsonc
"body": {
  "bounds": [214, 58, 426, 332],     // 站姿 idle 首帧的不透明包围盒 [x0, y0, x1, y1]，画布坐标（朝左）
  "headRatio": 0.30,                  // 从头顶往下 30% 算头（点击分区）
  "feetRatio": 0.15,                  // 从脚底往上 15% 算脚
  "feetY": 332,                       // 脚底基准线：站在地面上时，这条线贴着地面
  "mouth": [262, 120],                // 嘴的位置：喂食时食物飞向这里、吃东西的粒子从这里出（可选）
  "wall": { "contactX": 113, "feetY": 330 },  // 贴墙姿态下接触墙的那条竖线（朝左时在左边）和最低点，见 04 §5；默认值是工作台版式算出来的
  "ceiling": { "contactY": 40 }       // 倒挂姿态下接触天花板的横线（以后）
}
```

- 所有坐标是 **画布坐标、角色朝左**（和现有素材约定一致，朝右靠镜像）。镜像时程序自己换算。
- `bounds` / `feetY` / `wall.contactX` 由工作台在处理时从 alpha 自动测出来（05 §4），手写包可以不填，程序按 idle 片段第一帧现算一次并缓存。
- 接触点也可以 **按动作** 覆盖（某个攀爬动作的手比别的伸得远），写在动作的 `anchor` 字段（04 §3.2）；档案里的是默认值。
- `ClickZones.At` 改成用 `bounds` + `headRatio` / `feetRatio`，默认值等于现在的常量，老包点击分区不变。

## 4. 物理参数

```jsonc
"physics": {
  "weight": 1.0,        // 0.3～3；越重被甩出去飞得越近、落地越「沉」（只影响速度缩放和落地反应阈值）
  "bounce": 0.25,       // 0～0.8；撞墙 / 落地的反弹系数
  "walkSpeed": 1.0,     // 走路速度倍率，乘在步态的 stride 上（现在 stride 是按片段测的固定值）
  "climbSpeed": 1.0,    // 爬墙速度倍率
  "fragile": false      // true：摔重了会播「晕」而不是「落地」（04 §4.3）
}
```

`species` 给一组默认值：`flying` 的 `weight` 小、下落慢（以后可以「飞」而不是「掉」），`blob` 的 `bounce` 高。

## 5. 口味

```jsonc
"diet": {
  "likes": ["fish", "cake"],     // 内置食物 id（03 §2.3），吃到时心情加成 ×1.5、播 happy
  "dislikes": ["vegetable"],     // 吃到时心情 −，播 sad / angry，饱腹照加
  "appetite": 1.0                // 食量：一次喂食加的饱腹 ×1/appetite（大胃王加得少）
}
```

`persona.likes` 是给 LLM 的自由文本（「晒太阳」「肉干」），`diet` 是程序用的结构化食物 id，两者独立。工作台 ① 填写喜好时，
能匹配上内置食物的自动勾进 `diet.likes`。

## 6. 动态档案（不在包里）

随时间变的东西不放 `pet.json`，存在用户数据目录（06 §2）：

| 字段 | 含义 |
|---|---|
| `adoptedAt` | 第一次用这只宠物的时间（「认识多少天」） |
| `nickname` | 用户给它起的昵称（可选；对话里和气泡里用它替换 `persona.name`） |
| `needs` / `bond` | 见 02 |
| `stats` | 累计：被摸次数、喂食次数、陪伴的专注时长、被甩次数、爬墙次数……控制台「档案」页展示，也给亲密度和「成就」式的台词用 |
| `traitOverrides` | 用户覆盖的性格数值 |

## 7. 校验

- 数值字段超范围时夹到范围内并记日志，不拒绝加载（和 `persona` 的长度限制一样宽松）。
- `body` 里的坐标必须在画布内；`bounds` 面积小于画布 5% 或大于 95% 时忽略并现算。
- 食物 id 不认识的忽略（第三方包可能用了新版程序的食物）。
