# 07 分期计划

接在 pet-studio/08 的第四期（工作台 MVP）之后。原第五期里的「分段动作（睡觉、坐下）」并入本计划的姿态图（P2 / P3），其余第五期条目不变。
每一期结束时同样要求：`dotnet build`、单元测试、`--smoke`、三平台 release 构建通过。

## P1：档案与数值（不需要新素材）

> 状态（2026-11-05）：已完成。`dotnet build`、单元测试（312 个 + 16 个 Slow）、`--smoke`、macOS arm64 NativeAOT 发布和 AOT 冒烟通过。
> 和设计的出入：
> - 食物图标用 emoji（🍙🥛🥬🐟🍰🍦🍪），三个平台都有，不另外分发 PNG，也不用在 THIRD_PARTY_NOTICES 里记来源。
> - 「好久不见」是单独的事件 `life.returned {days}`（规则 `returned`），不是给 `app.started` 加数据：存档是在 PetLife 启动时读的，比打招呼早。
> - 叫醒：睡着时的单击由 `InteractionBehavior` 直接发 `pet.woken`（不发 `pet.clicked`），规则 `woken` 听它；规则的 `final` 开关也实现了，备用。
> - 内置角色补了 `profile`（性格、口味）和按亲密度解锁的台词；包版本小t 1.2.0、大肥鱼 1.2.0（`tools/pets/*.json`，`pack_pet.py` 原样带上 profile / stance / transition / anchor / unlock）。
> - 修了一个原有的测试隔离问题：`ModelCatalog` 在没设数据目录时读缓存会抛异常，协议测试单独跑时偶发失败；现在没目录就用内置快照。

内容：

- `profile` 解析（01），`ClickZones` 改为按 `body` 读，默认值等于现有常量
- `Life/`：数值、规则、存档、离线补算、亲密度等级（02、06 §1～§2）
- 触发条件 `need` / `bond`、新事件和默认规则（`hungry`、`feed`、`level-up`、`spammed`），台词按亲密度分组（06 §3）
- 随机链调制注入点（06 §3.3）
- 喂食：右键菜单子菜单、食物图标飞到嘴边、零食由番茄钟奖励（03 §2，方案 A）
- 状态浮层（03 §3）；控制台「状态」页（06 §5）
- Agent 情境层、对话加经验；`/v1/status` 和 `get_pet_status`（06 §4）
- 内置角色补 `profile`（性格、口味）和按亲密度分组的台词

验收：

- 关掉宠物体系时，随机链统计测试、所有 0.1.4 行为测试照旧通过。
- 用假时钟跑「一个工作日」：饿一次、喂一次、番茄钟 4 轮得 4 份零食、亲密度不超过每日上限。
- 周五退出、周一打开：饱腹 ≥ 35，播「好久不见」。
- 没有 `eat` / `hungry` 的老宠物：喂食播 `happy`（或 `click`），饿了播 `idle` + 气泡，不报错。

## P2：地面、重力、抛掷、姿态图

> 状态（2026-11-05）：已完成，含拖食物喂食（方案 B：从菜单选了食物后图标拿在光标上，移到宠物身上停 0.3 秒就喂，6 秒没喂到就自动飞过去）。
> 和设计的出入：
> - 没有新加 `ICursor`：现有的 `INativeWindow.CursorInWindow()` 在窗口外也读得到（macOS 用 mouseLocation、Windows 用 GetCursorPos 换算），
>   换算成画布坐标就够视线跟随、靠近光标、陪玩用。Linux 读不到光标，这几个互动在 Linux 上不发生。
> - 分段动作展开后过渡动作的 id 是 `<id>-in` / `<id>-out`，循环段保留原 id 并带上 `idle` 角色（作为这个姿态的待机）。
> - 拖拽速度采样用最近 100 毫秒；`PetBody.Toss` 给控制台「掉下来 / 甩一下」用。

内容：

- 放置模式和迁移（04 §2，L6）
- `Motion/`：`SurfaceMap`、`PetBody`（对齐、物理、`air` / `held`）、`StanceGraph`（含 `phased` 展开）（04 §3～§4、§9）
- Director：`Stance`、按姿态过滤、寻路、`stance:` 目标、`final` 规则
- `PetWindow` 拖拽速度采样、甩出去；`fall` / `land` / `dizzy` 规则
- 平台层 `ICursor.Position`；视线跟随、主动靠近（03 §4.3、§4.4）
- 拖食物喂食（03 §2.1 方案 B）
- 工作台：模板「吃东西」「下落」「落地」「晕乎乎」「饿了」「打哈欠」（地面组，首尾帧同图，不需要新关键帧）；⑥ 测 `body`

验收：

- 新安装：宠物站在任务栏 / Dock 上方；拖到半空松手会掉下来；甩到屏幕边会反弹；永远不会掉出屏幕（含拔掉副屏）。
- 老用户升级：仍是自由放置，行为和升级前一样。
- 多屏（主屏 + 不同 DPI、不同高度的副屏）下落、行走不出错。

## P3：爬墙、坐、睡

> 状态（2026-11-05）：代码完成；**内置角色的新片段还没生成**（要调付费的视频模型，按设计由人在工作台里做并验收），
> 所以小t、大肥鱼现在不会爬墙、坐、睡（姿态图里没有这些姿态，自动降级为不爬），吃东西 / 下落等也走回退链。
> 和设计的出入：
> - 工作台的坐、睡做成显式的过渡动作（坐下 / 坐着待机 / 起身，入睡 / 睡着 / 醒来），不用 `kind: phased`；运行时两种写法都支持。
> - 非地面姿态和过渡动作的片段按「画面锁定」定位（`Placement.FrameLocked`：画面 65% 高 = 身高 270，85% 地面线 = 脚底 330），
>   不按人物包围盒量，换姿态时角色不会忽大忽小。贴墙关键帧左缘在画面 22%，映射到画布接触线默认约 113。
> - 关键帧的大小按姿态给比例（贴墙 1.0、坐 0.72、睡 0.5 倍站姿高度），脚底统一对齐 85%。
> - 召唤（全局快捷键 ⌃⌥P / Ctrl+Alt+P）已做：平台层加了 `IGlobalHotkey`（能力 `GlobalHotkey`）。macOS 用 Carbon 的 RegisterEventHotKey
>   （不需要辅助功能 / 输入监控权限）；Windows 和 Linux（X11）每 120 毫秒查这三个键的按下状态（只看这三个键）。
>   按下后宠物到光标所在屏幕、光标正下方的地面上，发 `hotkey.summon`（规则 `summon` 打招呼），隐藏着的也会显示出来。控制台「位置」页可关。
> - 用模拟鼠标（CGEvent）在真实窗口里试了甩出去：发现并修了一个单元测试测不出的问题——松手进入下落时没通知窗口，物理定时器没启动，宠物停在半空。
>   修好后真实窗口里甩出去、穿过主副屏交界、落到副屏底边都正常。

内容：

- 工作台 ③ 选装关键帧（贴墙、坐、睡），④ 按姿态分组和可用性判定，过渡动作用首尾帧不同模式，新的公共前缀（05 §1）
- ⑥ 测接触点、攀爬步态，新质检项；⑦ 试玩按钮；⑧ `minAppVersion` 和导出前校验
- 运行时：贴墙对齐、过渡动作二维插值、墙上的随机链、`climb-up` 规则（04 §5）
- 坐 / 睡姿态；哄睡、叫醒、夜里犯困（03 §1）
- 「动作」页给已有宠物补新姿态（05 §2）
- **用工作台给小t、大肥鱼生成贴墙 / 睡觉 / 吃东西等片段**，更新内置包（作为工作台新模板的验收样本；费用预估：每只约 60～80 秒视频）
- 逗它玩、召唤（依赖全局快捷键）

验收：

- 工作台里做一只新宠物，勾上「贴墙」，从生成到在桌面上看到它爬墙，全程不离开程序。
- 贴墙时手脚贴着屏幕边，左右墙都对（镜像、缩放 0.5～2、Retina / 150% DPI）。
- 只生成了一半墙组动作的工程：工作台标「不可用」，导出的包里没有墙组；手改 `pet.json` 塞进去的残缺墙组在加载时被忽略。
- 用旧版程序打开带 `stance` 的新包：被 `minAppVersion` 拦下并提示升级。

## P4：以后（按反馈挑）

> 状态（2026-11-05）：「站在窗口上」和「倒挂天花板」已做；「认真养」、自定义食物、背包装饰、多只宠物仍按反馈再定。
> - 站在窗口上：平台层加了 `IWindowSurfaces`（能力 `WindowSurfaces`）。macOS 用 CGWindowListCopyWindowInfo（只读 bounds / layer / pid，
>   不读标题，不需要屏幕录制权限）；Windows 用 EnumWindows + DWMWA_EXTENDED_FRAME_BOUNDS（跳过隐藏、最小化、cloaked、工具窗口）；
>   Linux 只在 X11 会话下用 _NET_CLIENT_LIST_STACKING + _NET_FRAME_EXTENTS。默认关（L9），控制台「位置」页打开后每半秒刷新一次。
>   顶边被更前面的窗口挡住的部分、最大化 / 全屏窗口的顶边、太窄的窗口都不算；宠物落下时会落在窗口顶上，在上面走不会走出这段，
>   走到尽头有时会跳下去；窗口移动时跟着移，窗口关了、最小化、被挡住就掉下去。
> - 倒挂：姿态 `ceiling`，只能从墙顶翻上去（头离屏幕顶不到三分之一身高），在上面沿 X 爬，待久了松手掉下去或回到墙上。
>   工作台 ③ 多了「倒挂」关键帧（顶边对齐画面 12%，画布上贴天花板的线默认约 27），④ 多了一组 5 个模板；导出时从倒挂待机量 `body.ceiling.contactY`。

## 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 数值体系让用户有负担 / 觉得被催 | 卸载、关提醒 | 纯陪伴基调（L1）；不弹通知、不朗读；离线下限保护；整套可关 |
| 平衡没调好（饿太快、升级太慢） | 体验差 | 所有常量集中在 `LifeTuning`；内测期打开「快」速度看全流程；控制台的「为什么」帮助发现问题 |
| 视频模型做不好贴墙（手脚离墙、身体漂移） | 爬墙「飘」、要反复重做费钱 | 贴墙关键帧自动检查；贴墙稳定、原地两项质检；墙组整组做之前先只做「贴墙待机」试一段 |
| 过渡动作首尾帧不同，模型过渡不自然 | 上墙 / 坐下很突兀 | 时长给足（4s）；模板强调「位移尽量小」；位移由窗口插值承担 |
| 每帧移动窗口的开销（物理 60Hz） | CPU 占用、某些平台卡顿 | 只在 `air` 时跑 60Hz；落地即停；省电模式下抛掷直接落地不播轨迹 |
| 多屏 / DPI / 工作区变化下的位置错误 | 宠物消失在屏幕外 | `SurfaceMap` 夹紧；屏幕变化时重建并校验；专门的多屏测试 |
| 旧版程序加载新包把攀爬当地面动作 | 体验崩坏 | 导出时自动设 `minAppVersion`；`PetPack` 加载时校验 |
| 平台差异（Linux Wayland 不能定位窗口、窗口枚举权限） | 功能缺失 | 按 `PlatformCapabilities` 置灰；窗口顶边功能最后做、默认关 |
| 内置角色补素材的费用 | 一次性成本 | 先做小t 验证模板，再做大肥鱼；成本记在账本里 |
