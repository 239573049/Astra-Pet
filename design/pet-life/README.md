# 宠物体系：档案 · 需求与亲密度 · 互动 · 空间移动

这组文档设计「让宠物像一只活的宠物」的四件事：

1. **更细的宠物档案**：角色包里除了人设文本，还要有性格数值、身体尺寸和接触点、物理参数、口味，程序拿它们驱动行为，而不是只给 LLM 看。
2. **需求与亲密度**：饱腹、精力、心情这类短期需求，和亲密度这种长期关系；数值影响动作、台词、Agent 的语气，但不惩罚用户。
3. **更多互动**：喂食、甩出去、逗它玩、哄睡、连点、视线跟随……全部走现有的「事件 → 规则 → 动作」管线。
4. **空间移动**：引入地面、墙、（以后）天花板和窗口顶部；宠物能站在任务栏上、被扔出去会掉下来、走到屏幕边上能爬墙。

同时扩展工作台（新的关键帧、新的动作模板、自动标注接触点），让自己做的宠物也能有这些能力。

决策清单已全部定下（都按推荐项），P1～P3 已实现，P4 里的「站在窗口上」「倒挂天花板」也已实现（2026-11-05，分支 `feat/action-system`，状态和出入见 [07-roadmap.md](07-roadmap.md)）。

## 现状（feat/action-system，2026-11-05）

和这次设计有关的事实：

- **宠物没有状态。** 除了「当前在播哪个动作、朝哪边」，宠物没有任何会随时间变化的量。点一万次和一次都一样，三天不开程序回来也一样。
- **档案只有人设文本。** `pet.json` 的 `persona`（名字、身份、性格、说话方式、喜好……）只拼进系统提示词，程序本身不读；
  `render` 里有 `bodyHeight` / `feetY` 两个常量，点击分区 `ClickZones` 也是写死的「头顶 y≈60、脚底 y≈330」。
- **位置只有一维。** `PetWindow` 走路只改 X（`WalkPlanner` 在工作区左右边缘之间挑方向和距离）；Y 由用户拖到哪就是哪，宠物可以悬在屏幕中间。
  没有「地面」「墙」的概念，松手不会下落，也不知道自己贴着屏幕边。
- **拖拽是一个循环动作。** `Director.BeginDrag/EndDrag`，松手就回待机；拖拽的速度不记录，没法「甩出去」。
- **动作有角色、有分段的数据结构，但姿态是隐含的。** `ActionKind.Phased`（进入 / 循环 / 退出）已经在 `ActionDef` 里，
  睡觉这类「换个姿势待一会儿」排在原路线的第五期。所有动作默认都是「站在地上」。
- **互动只有四种。** 单击（分头 / 身体 / 脚三区）、双击（开对话）、摸头（悬停来回划）、拖拽。
- **工作台的关键帧只有站姿**（和分段走路用的侧身）。所有模板都是「首尾帧同一张站姿图、原地动作」。
- **平台层没有窗口枚举。** `IPlatform` 能拿到自己的窗口、光标位置、空闲时间、是否在放声音，拿不到其他应用窗口的位置。

## 设计原则（沿用 design/README.md 与 pet-studio，并补充）

- **陪伴，不制造焦虑。** 桌宠是工作时在旁边的伙伴，不是让人有负罪感的电子宠物。数值低时宠物会「表现」出来（饿了摸肚子、困了打哈欠），
  但不会因为用户忙了一周没管它就生病、死掉、清空亲密度。不弹系统通知催用户。
- **数值驱动表现，表现走现有管线。** 需求和亲密度不直接调 Director，只做三件事：发事件（交给触发规则）、调制随机链权重、写进 Agent 的情境层。
- **缺素材时优雅降级。** 新角色全部可选；没有 `eat` 就用 `happy`/`click` 加食物气泡；没有贴墙片段就不爬墙；老角色包的体验不变差。
- **五个必需角色不变（D14）。** 新能力不提高做一只宠物的门槛。
- **数值可见、可调、可关。** 控制台能看到每个数值和它为什么变；变化速度可调；整个体系可以关掉退回 0.1.x 的纯观赏模式。
- **Core 可测试。** 数值模拟、姿态图寻路、物理积分、表面几何都是纯计算，放在 Core，用假时钟和固定种子测。
- **隐私。** 窗口顶部功能只读窗口矩形，不读标题和应用名；所有数值只存在本地。
