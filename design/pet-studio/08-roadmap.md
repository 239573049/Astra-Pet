# 08 分期计划

每一期结束时都能发版：`dotnet build`、单元测试、`--smoke`、三平台 release 构建都通过（沿用 design/04-migration.md 的要求）。

## 第一期：动作模型与触发（行为不变的重构）

> 状态（2026-11-04，分支 `feat/action-system`）：代码完成，`dotnet build`、单元测试（146 个）、`--smoke` 通过；控制台「动作」页的手动验收还没做。
> 和设计的出入记在 02 §3.2「第一期实现时的调整」。07 里「包内不能有没被引用的 webm」和大小上限的检查在第二期补上了。

内容：

- `Actions/`：`ActionDef`、`ActionSet`、格式 1 合成、角色与回退链（01）
- `Triggers/`：事件总线、规则、默认规则、`TriggerEngine`（02）
- `PetDirector`：`Request`、优先级、待播队列、循环、按 `ambient` 抽取；`PetWindow` / Behaviors / `PetCompanion` 改为发事件
- `PetPack` 能读格式 2（先不必有人用）
- 控制台「动作」页：列表、▶ 预览播放、启用 / 禁用、权重、描述、台词（覆盖层 `actions.user.json`）

验收：

- 不改任何设置时，随机链比例、点击 / 拖拽 / 摸头 / 番茄钟 / 听歌的反应和 0.1.4 一致（02 §8 的测试全绿）。
- 在控制台把「抱水豚」的权重拉到 0、给「开心挥手」改台词，重启后保留；升级内置包后仍然保留。

## 第二期：Agent 动作与新提示词

> 状态（2026-11-04，分支 `feat/action-system`）：六项都已实现，`dotnet build`、单元测试（217 个）、`--smoke` 通过，NativeAOT 发布版上手动跑通了 HTTP 接口和 `AstraPet mcp`。
> 下面的验收（多模型对话评测、Claude Code 实际接入）还没做。和设计的出入：Chat Completions 不发 `parallel_tool_calls`（不少网关不认，见 03 §1.3）；外部接口见 03 §2.4。
> 之后补上了：情境层的「连续用电脑多久」（满 30 分钟才写，平台不支持空闲检测时不写）、记忆的 replace / with、07 §4 的引用完整性和大小上限。

内容：

- `ILlmClient` 支持工具调用：内容块消息模型、三种协议的工具序列化 / 解析、最多 3 轮的调用循环、`ToolSupport` 探测（03 §1.2～§1.5）
- `play_action` 工具、动作清单生成、`chat.thinking` / `chat.action` / `chat.replied` 事件（03 §1.1、§1.6）
- 分层系统提示词、情境层、人设字段和迁移（03 §3）
- 内置的小t、大肥鱼升级为格式 2：补动作描述和人设（`pack_pet.py --format 2`）
- 「智能」页：人设 / 用户补充两个输入框 + 完整预览；提供商表单加「工具支持：自动 / 开 / 关」和测试结果
- 外部 Agent：本地 HTTP 接口 + `AstraPet mcp` 子命令，默认关闭（03 §2，D4）

验收：

- 三种协议各选一个支持工具的模型（比如 Chat Completions 一个、Responses 一个、Anthropic 一个），再加一个本地模型，各跑 30 句固定对话：
  人工抽查动作与语义的匹配度；统计「只调工具不说话」触发第二轮的比例和平均延迟。
- 不支持工具的模型：自动探测后不再带工具，回复后宠物随机做一个 click 反应，和 0.1.4 一样；对话不报错。
- 选小t 时宠物自称小t，选大肥鱼时自称大肥鱼。
- Claude Code 通过 MCP 让宠物做动作、说话；令牌错误时被拒绝；外部接口关闭时端口不监听。

## 第三期：处理管线与导入

内容：

- ffmpeg 构建扩展：VP9 编码、H.264 解码、mov / webm（06 §5，D11 方案 A），selftest 补对应用例，记录三平台体积增量
- C# 处理管线、质检、预览图（06）
- 「动作」页的「导入透明视频 / 导入绿幕视频」（01 §4.3）

验收：金标准测试通过（C# 处理小t 的原始 mp4，和 `process.py` 结果一致）；导入一段绿幕 mp4，几分钟内在宠物上看到新动作。

**状态：已完成（2026-11-04）。**
- ffmpeg：多开了 hevc 解码器（7.1.1 的 h264 依赖它带进来的 aom_film_grain），macOS arm64 体积 1.58 → 3.64 MB；selftest 加了 H.264 解码和从标准输入编 VP9 再解回来查 alpha。
  ffmpeg 7.1 里输入写 `-` 要 fd 协议，精简构建没开，编码器的输入要写 `pipe:0`。
- 管线：`src/AstraPet.Infrastructure/Studio/Processing/`，缩放和模糊按 Pillow 逐字节复刻（不用 SkiaSharp，见 06 §2.2）。
  金标准（`[Trait("Category","Slow")]`）：小t 的 idle / click / move / drag 四段，质检指标和 process.py 一致、逐帧 alpha 平均差 < 3/255；
  Release 下每段 10～14 秒，比 process.py 快。
- 导入：「动作」页「添加动作 → 导入视频」，自动判断带透明通道 / 纯色背景，处理后看预览和质检再加到宠物上，加完立即播一次；用户加的动作可以删除。
  导入一段 10 秒绿幕 mp4 到在宠物上播放，Debug 构建约 35～50 秒。move 角色需要步态，导入暂不支持；预览图拼图（06 §3.3）、首尾修复（§3.4）、报告落盘留给工作台。

## 第四期：工作台 MVP

内容：

- 生成模型提供商：方舟视频任务协议、OpenAI Images、Seedream（05）
- 工作台 ⓪～⑧（04），只做首尾帧同图模式，不做分段动作
- 格式 2 导出、附带源文件、安装到我的角色（07）
- `ICostGate`、任务记录落盘与恢复、账本

验收：

- 一个没用过命令行的人，从一句描述做出一只能用的宠物，全程不离开程序。
- 中途强退程序，重开后正在生成的任务继续轮询，没有重复提交（看账本和服务端的任务列表）。
- 导出的包在另一台机器（另一个平台）上能直接用。

**状态：代码完成（2026-11-05），真实付费接口的验收还没做。**
- 提供商：`src/AstraPet.Infrastructure/Studio/Providers/`（方舟视频任务、OpenAI Images 生成 / 编辑、方舟 Seedream），配置存在设置的
  `MediaProviders` 里，四个预设带参考单价；「测试连接」只发不计费的请求。请求、任务记录、日志、账本里没有 Key，图片 base64 截断。
- 任务队列 `VideoTaskQueue`：全程序一个，最多同时 2 段；提交后立刻写 `raw/<动作>/take-NNN.task.json` 再轮询（10 秒起、×1.5、封顶 30 秒），
  提交失败不重试、不留记录；启动时把所有工程没完成的任务接着查（单元测试覆盖了强退后恢复不重复提交）。
- 工作台窗口：控制台「角色 → 打开角色工作台」。九步的状态按文件哈希推出来（上游改了下游标「需更新」，不删产物）；
  ② 选设定图时按角色颜色自动选抠像色，③ 选站姿后本地抠图、检查、合成首尾帧；⑤ 一次确认整批，下载完自动进 ⑥ 处理，
  每个动作默认采用第一段处理好的；⑦ 临时打包换到桌面上试（不改设置）；⑧ 导出后按加载角色的同一套检查验一遍，「安装到我的角色并使用」一键装上并切换。
  所有付费调用都经过费用确认框（`ICostGate`），账本在工程目录的 `ledger.jsonl`。
- 端到端（`StudioEndToEndTests`，Slow）：用小t 的参考图和原始视频走 ②～⑧（⑤ 用现成视频代替），处理 5 段、导出 8 MB 的包，
  拷进一个空的角色目录按程序启动的路径扫描、加载通过。Debug 构建可以用 `ASTRA_PET_DATA=<临时目录> ASTRA_PET_STUDIO=1
  ASTRA_PET_STUDIO_DEMO=characters/小t ASTRA_PET_STUDIO_SNAPSHOT=<目录>` 搭演示工程并截图每一步。
- 生成接口暂时写死 NextCoWork，⓪ 只填 Key、选视频模型（Seedance 2.5 / 2.0 / 2.0 Fast / 2.0 Mini，见 05 §1）；图片用 `gpt-image-2.5-flare`。
- ④ 可以加自定义动作：名称 + 一句话描述 + 触发时机（多选）+ 时长，提示词按「准备 → 描述 → 回到首帧姿势」的时间轴生成，之后可改。
- 界面用 Arc 组件（Sidebar、Card、SegmentedControl、ChipGroup、FileDropzone、Progress、NumberField），无边框窗口，外框行为在 `WindowChrome`。
- 没做：设定卡的「帮我完善」（LLM 生成）、首尾修复（06 §3.4）、⑥ 里直接播放视频（目前看缩略图 + 质检，播放用 ⑦）。

## 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 生成费用超出用户预期 | 用户流失、投诉 | 每次付费前确认；估算醒目；「先生成一段试试」是默认推荐路径；账本可查 |
| 视频模型不守约束（推镜头、出现手、首尾不一致） | 要重做，费钱 | 公共前缀固化已知的坑（04 §3 ④）；质检自动发现；首尾修复兜底 |
| 角色一致性差（侧面、背面和正面不像） | 宠物质量差 | ② 设定图 + ③ 以设定图为参考生成站姿；仍不理想时引导用户多试几次站姿 |
| 抠像失败（角色颜色接近抠像色、半透明特效） | 边缘脏、出现雾 | 自动选抠像色；抠像参数可调；提示词要求不透明特效 |
| 提供商 API 变化 / 模型下线 | 生成失败 | 地址、模型、扩展参数都可配；错误信息原样展示；协议细节集中在一个客户端类里 |
| ffmpeg 体积和许可 | 所有用户的安装包都变大、合规 | 已定扩展现有构建（D11）；记录每次体积增量，过大时再拆成按需下载；只用 LGPL 范围内的组件 |
| 常用模型不支持工具调用（D3 只做了工具调用） | 这些模型下宠物不能按对话内容做动作 | 自动探测并降级为随机 click（不比现在差）；第二期验收时统计常用本地模型的支持情况，不理想就把内联标签作为兜底加回来 |
| 工具调用多一轮往返 | 回复变慢 | 收到调用立即开始播动作；文字和调用同时返回时不发第二轮 |
| 五类必需动作（D14） | 自己做宠物门槛高，move / turn 最难生成好 | 工作台模板里的 move / turn 提示词重点打磨；质检给出针对性的重做建议；步幅在试玩时现场调 |
| 用户用他人的角色或真人照片生成 | 版权、肖像权 | ① 和 ⑧ 提示；导出时必须填许可；程序不做内容审核，责任在用户（在使用说明里写清楚） |
| 第三方包的人设做提示词注入 | 宠物说出奇怪的话 | 长度限制、平台准则在前、可一键不用包里的人设；第一期只有纯表现的 `play_action` 工具，以后的有副作用工具执行前必须用户确认 |
| NativeAOT 兼容（SkiaSharp、JSON、HTTP 服务） | 发布构建失败 | 每期 CI 跑三平台 AOT 构建；JSON 全用源生成 |
