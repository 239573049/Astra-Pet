# 04 宠物工作台（Studio）

## 1. 形态【待定 D12】

| 方案 | 说明 | 取舍 |
|---|---|---|
| **A. 程序内的独立窗口** | 控制台「角色」页的「新建宠物」、托盘菜单「宠物工作台」打开 | 复用设置、提供商、ffmpeg、宠物窗口（试玩直接用真窗口）；做完一键装上。推荐 |
| B. 单独的程序 | `AstraPet Studio` | 发布、更新、共享配置都要多一套 |
| C. 网页 | 在线工作台 | 要服务器、要处理用户的密钥和素材，和现在纯本地的定位不符 |

代码分层沿用 design/01-layering.md：

```
AstraPet.Core/Studio/            工程模型、步骤状态机、动作模板、费用估算 —— 纯逻辑，可测试
AstraPet.Infrastructure/Studio/  图片 / 视频提供商客户端（05）、处理管线（06）、导出（07）
AstraPet.App/Studio/             StudioWindow 和每一步的视图
```

## 2. 流程总览

```
 ⓪ 绑定模型 ─▶ ① 描述角色 ─▶ ② 全方位设定图 ─▶ ③ 站姿与首尾帧 ─▶ ④ 规划动作 ─▶ ⑤ 生成视频 ─▶ ⑥ 处理与质检 ─▶ ⑦ 试玩调整 ─▶ ⑧ 导出
   图片/视频/对话   文字 + 参考图     图片模型 · 选候选    图片模型 · 自动合成    对话模型辅助     视频模型 · 付费     本地 · 自动          真实宠物窗口       .astrapet
```

- 每一步有状态：未开始 / 进行中 / 完成 / **过期**（上游改了）。改了上游，下游标成过期但 **不删除**，用户决定重做哪些——视频很贵，不能因为改了一个字就全部作废。
- 任何时候可以关掉窗口，下次打开从上次的位置继续（工程状态全部落盘，见 §4）。
- ⑤ 之前都很便宜（几张图几毛钱），所以鼓励在 ②③ 多试；⑤ 之前有明确的「费用确认」关口。

## 3. 每一步

### ⓪ 绑定模型

| 用途 | 必需 | 用在 | 说明 |
|---|---|---|---|
| 图片模型 | ✅ 第 ① 步之前 | ②③，分段动作的关键帧 | 必须支持「参考图 + 文字 → 图」（图像编辑）；见 05 §3 |
| 视频模型 | ✅ 第 ⑤ 步之前 | ⑤ | 火山方舟任务协议，必须支持首尾帧；见 05 §2 |
| 对话模型 | 可选 | ①④ 的提示词助手、生成人设 | 直接用控制台「智能」页已配好的当前模型 |

这一步是工作台入口的门槛：没绑图片模型时，其他步骤灰掉，页面上只有绑定表单和「测试连接」。视频模型可以晚点绑，到 ④ 结束时再拦。

### ① 描述角色

输入（至少一项）：

- **文字描述**：「一只橘色的胖柴犬，戴红色围巾，圆滚滚的」
- **参考图**：1～4 张（设定图、照片、手绘草稿）。界面上提示：不要用你没有权利使用的形象（真人照片、他人原创角色），导出时要填许可。

选项：

- 画风：Q 版 2.5D / 日系动漫 / 3D 手办风 / 像素风 / 手绘水彩 / 自定义（影响后面所有提示词）
- 体型：Q 版头身比（2～5 头身，默认 3.5），或「动物 / 非人形」
- 伙伴：可选「脚边有一个常驻小伙伴」（像小t 的水豚）——会增加生成难度，默认不开

对话模型可用时，有一个「帮我完善」按钮：把描述扩写成结构化的 **角色设定卡**，后面的提示词都从这张卡填：

```jsonc
{
  "name": "柴柴",
  "species": "柴犬",
  "appearance": "橘色短毛、白色口鼻和肚皮、卷尾巴、戴红色针织围巾，圆滚滚的 Q 版身材",
  "palette": ["#E8954A", "#FFFFFF", "#C8282E"],
  "props": [],
  "persona": { "personality": "懒洋洋但很黏人", "speech": "说话慢吞吞，句尾爱加「汪」" }
}
```

`persona` 就是导出时写进包里的人设（03 §3.3），用户在 ⑧ 还能改。

### ② 全方位设定图

一次生成 2～4 张候选（数量可调，按张计费），每张是一张 **角色三视图设定稿**：同一角色的正面、¾ 侧面、正侧面、背面全身像，纯白背景，下方可选一排表情。

- 有参考图时走图像编辑接口（参考图 + 提示词），没有时走文生图。
- 用户操作：选一张 / 全部重来 / 改提示词再来 / 对某一张「局部再改」（再次编辑，带上这张图）/ 上传自己画好的设定图跳过生成。
- 程序检查：图像尺寸、是否大致是多视图（可选，用对话模型的视觉能力判断；没有就不检查）。

为什么要这一步：后面所有动作都只给视频模型一张正面站姿图，转身、侧身跑这些动作里模型要「猜」侧面和背面长什么样。
设定图本身不进视频请求（D7：首尾帧模式不能混用参考图），它的作用是 **让站姿图更准**——③ 生成站姿时把设定图作为参考，
并且导出时作为 `source/sheet.png` 随包保存，以后给这只宠物加动作、做分段动作的关键帧时还要用。

### ③ 站姿与首尾帧

1. **标准站姿图**：参考 ② 选中的设定图（+ 用户原始参考图）生成一张正面全身站姿。提示词模板固化了这些要求（来自小t 的经验）：
   正面直立、双脚并拢站稳、双臂自然下垂稍离身体、闭嘴微笑、看向正前方；只画一个角色；完整全身、四周留白；
   **背景用纯色抠像色**（见下）；不要地面、阴影、文字、色卡。生成 2 张候选供选。
2. **抠像色自动选择**：分析站姿图主体的色相分布。主体里绿色很少 → 用 `#00FF00`；有大量绿色（绿头发、绿衣服）→ 改用 `#0000FF`
   或 `#FF00FF`。选定的颜色写进工程，后面的视频提示词、抠像参数都跟着它。这是现在脚本没处理的坑：绿色角色在绿幕上抠不干净。
3. **自动检查**：主体是否完整在画面内（四边留白）、有没有多个主体、背景是否纯净（背景像素的颜色方差）、头身比是否接近 ① 选的值。
   不过关的给出原因，让用户重新生成。
4. **合成首尾帧**：不调模型。把站姿图抠出来，放到 1280×720 纯色画布上，头顶在 20%、脚底在 85%、水平居中（`make_first_frame.py` 的规则）。
   预览里叠一条脚底基准线。

### ④ 规划动作

左边是动作列表，默认带上「基础套装」，用户可以增删、改：

| 模板 | 角色 | 必需 | 默认时长 |
|---|---|---|---|
| 待机呼吸 | idle | ✅ | 10s |
| 被拎起悬空 | drag | ✅ | 6s |
| 开心挥手 | click happy greet | ✅ | 8s |
| 原地小跑（朝左侧身） | move | ✅ | 10s |
| 东张西望 | turn | ✅ | 8s |
| 害羞 | click shy | | 8s |
| 庆祝跳起 | celebrate happy | | 6s |
| 伸懒腰 | stretch | | 8s |
| 喝水 | drink | | 8s |
| 歪头疑惑 | confused | | 6s |
| 难过低头 | sad | | 8s |
| 跟着音乐摇摆 | sing | | 10s |
| 打瞌睡（分段：入睡 / 睡着 / 醒来） | sleep | 第二期 | 6 + 8 + 6s |
| 自定义 | 用户选 | | 用户填 |

每个动作的提示词 = **公共前缀**（工程级）+ **动作提示词**（模板 + 角色设定卡填空）。对话模型可用时，「帮我写」按钮按角色设定卡改写，
让动作贴合角色（柴犬的「开心」是摇尾巴转圈，不是挥手）。

公共前缀模板（来自小t 的 `prompt_prefix` 和踩过的坑，`{}` 由工程填）：

```
桌面宠物循环动作视频。首帧和尾帧是同一张图：{角色一句话外观}站在纯{抠像色名}背景前。要求：
1. 背景始终是纯{抠像色名} {抠像色值}，没有阴影、地面或其他物体；
2. 镜头固定，全程全身远景，不推拉摇移，不切特写；
3. 角色原地动作，不在画面里移动，跳起后落回原位；
4. 角色的比例、外貌和服装始终与首帧一致；
5. 画面里只有这个角色{和它的伙伴}，不出现手、手指或其他人物；
6. 特效和道具画成不透明的实心卡通样式，不要半透明或发光，结束前完全消失；
7. 最后一秒回到与第一帧完全一致的姿势和位置。
动作：
```

动作提示词按时间轴写（「0~2秒……；2~7秒……；7~10秒回到初始姿势」），模板里时间按所选时长自动缩放。

底部是 **费用估算**：`Σ 时长 × 单价(分辨率)`，单价来自提供商配置里用户可编辑的价格表（05 §4），标明「估算，以账单为准」。
旁边一个分辨率切换（480p / 720p）和「先生成一段试试」的推荐按钮——先只生成待机，看效果满意再批量。

参考数字（按 `characters/小t/README.md` 记录的单价）：基础套装 5 段共 42 秒，720p 约 63 元、480p 约 28 元；小t 实际做 7 段 + 重做 2 段花了约 191 元（含 480p 试验）。

### ⑤ 生成视频

- 点「开始生成」弹确认框：段数、总时长、估算费用、提供商和模型。确认后才提交。
- 任务队列：并发数默认 2（可调），每个任务 **先把任务 id 写进工程再轮询**，程序重启后接着查同一个任务，绝不重复提交（`generate.py` 的做法）。
- 每段卡片显示：排队 / 生成中（已用时）/ 下载中 / 完成 / 失败（错误信息原文）。失败的可以重试（会再次计费，再确认一次）。
- 成功立即下载（链接通常 24 小时过期），下载完自动进入 ⑥ 的处理。
- 同一动作可以生成多次（多个 take），都保留，用户在 ⑥ 里选用哪一个。
- 每次提交写一条账本记录（§4 的 `ledger.jsonl`）：时间、提供商、模型、参数摘要、估算、实际用量（任务结果里的 `usage`）。

### ⑥ 处理与质检

下载完的每一段自动跑 06 的处理管线（本地，免费），结果：

- **预览播放器**：可切换背景（棋盘格 / 深色桌面 / 浅色桌面），可逐帧、可循环播放看首尾衔接。
- **质检指标**（06 §4），超阈值的标黄并给出「建议重新生成」及原因（比如「首尾不一致，循环时会跳一下」「人物在画面里漂移了 60px」）。
- 每段可以：采用 / 换一个 take / 重新生成（回到 ⑤）/ 调抠像参数后重新处理（免费）/ 修首尾（自动交叉淡化，见 06 §3.4）。
- 只有「采用」的 take 会进入试玩和导出。

### ⑦ 试玩与调整

- 「放到桌面试试」：开一个临时的宠物窗口（独立的 `PetDirector` + 工程里的动作集），和正式宠物并排，真实地跑随机链、响应点击和拖拽。
- 右侧面板实时调：走路步幅 `stride`（拖动滑块，窗口里立即看到脚有没有打滑）、每个动作的随机权重、是否镜像、台词、角色、描述。
- 人设：显示 ① 生成的人设，可编辑；「和它聊两句」用当前对话模型 + 这个人设试聊，验证说话风格和 `play_action` 调用（当前对话模型不支持工具时提示）。

### ⑧ 导出

- 元数据：id（从名字自动生成拼音 / 英文 slug，可改）、显示名、作者、许可（预设：保留所有权利 / CC BY 4.0 / CC BY-NC-SA 4.0 / 自定义）、主页、署名。
- 预览图：自动生成（每个动作抽一帧拼成网格，等同 `preview.py`），可换。
- 选项：☑ 附带源文件（设定图、站姿、首尾帧、提示词，不含原始 mp4；约多 2～5 MB，以后能给这只宠物加动作）。
- 按钮：「导出 .astrapet…」（选位置保存）、「安装到我的角色并使用」（拷进用户角色目录，切换过去）。
- 导出前校验：必需角色齐全、id 合法、所有片段通过加载检查（用 `PetLibrary.Load` 真加载一遍）。

  project.json            工程状态：每步的输入、选中的候选、参数、步骤状态、输入哈希（判断过期）
  inputs/                 用户上传的参考图（复制进来，不引用原路径）
  sheet/cand-001.png …    ② 的候选；选中的记在 project.json
  figure/cand-001.png …   ③ 站姿候选
  figure/keyed.png        选中站姿抠出来的透明图
  first_frame.png         ③ 合成的首尾帧
  keyframes/<名字>.png     分段动作的其他关键帧（第二期）
  raw/<动作 id>/take-001.mp4
  raw/<动作 id>/take-001.task.json   提交后立刻写，记录任务 id、状态、请求摘要（不含密钥和图片 base64）

- `project.json` 有 `version` 字段，以后改结构时迁移。
- 工程列表在工作台首页：名字、缩略图、进度、已花费估算；可以复制工程（「以此为基础新建」，D2 方案 C 也走这里：从一个格式 2 的包的 `source/` 建工程）。
- 原始 mp4 很大（一段 10s 720p 约 5～15 MB），工程首页提供「清理原始视频」（保留采用的 take）。

## 5. 生成模式与连贯性【待定 D7】

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 首尾帧同图** | 每个动作的首帧和尾帧都是同一张站姿图 | 每段都从同一站姿开始、回到同一站姿，片段之间无缝衔接；小t 7 段首尾 IoU 都 ≥0.995，已验证 | 侧面、背面靠模型猜；不能做「换姿势待着」的动作 |
| B. 参考图模式 | 设定图作为参考图，文字描述动作 | 侧面背面更准 | 首尾不保证一致，循环会跳，要靠后处理硬接；人物位置大小也不固定 |
| **C. 首尾帧异图** | 首帧站姿、尾帧另一个姿势（坐 / 躺） | 能做分段动作（01 §3.3） | 要额外生成关键帧，且关键帧和站姿图要严格同一角色、同一位置大小 |

推荐 A 为主（第一期全部用 A），C 只用于分段动作（第二期）。B 不推荐。

## 6. 状态机（Core）

```csharp
public enum StepId { Bind, Describe, Sheet, Figure, Plan, Generate, Process, Tryout, Export }
public enum StepState { Locked, Ready, Running, Done, Stale }

public sealed class StudioProject
{
    public StepState StateOf(StepId step);       // 由各步的输入哈希和产物是否存在推出来，不单独存
    public IReadOnlyList<StepId> Invalidated(StepId changed);   // 改了这一步，哪些下游会过期
}
```

付费操作只在 Infrastructure 的客户端里发生，Core 里的状态机只决定「能不能点」。所有付费操作走同一个 `ICostGate`：

```csharp
public interface ICostGate
{
    // 弹确认框（App 实现）；返回 false 就不提交
    Task<bool> ConfirmAsync(CostEstimate estimate, CancellationToken ct);
}
```

## 7. 不做的事（第一期）

- 不做逐帧编辑、不做骨骼动画、不做把视频拆成精灵图。
- 不做云端工程同步、不做动作市场。
- 不自动判断「生成结果好不好看」——只给客观指标，主观判断交给用户。
