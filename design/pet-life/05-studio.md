# 05 工作台扩展

工作台（pet-studio/04）现在的模型是：**一张站姿首尾帧 + 一组原地动作**。宠物体系需要三类新东西：

1. **档案**：性格、口味、物理参数要在做宠物时就填上（①），身体接触点在处理时自动测（⑥）。
2. **更多关键帧**：贴墙、坐、睡（以及以后的倒挂）。每个关键帧是一个新的姿态的「站姿」。
3. **更多动作模板**：吃、饿、打哈欠、晕、下落、落地、贴墙待机、攀爬、上墙 / 下墙、坐下 / 起身、睡觉……按姿态分组，过渡动作用首尾帧不同的模式（D7 方案 C）。

## 1. 步骤的变化

```
⓪ 绑定模型 ─▶ ① 描述角色 ─▶ ② 设定图 ─▶ ③ 关键帧 ─▶ ④ 规划动作 ─▶ ⑤ 生成 ─▶ ⑥ 处理质检 ─▶ ⑦ 试玩 ─▶ ⑧ 导出
               + 性格 / 口味           站姿 + 选装姿态   按姿态分组                + 接触点测量   + 爬墙 / 甩 / 喂   + profile
```

步骤数不变，③ 和 ④ 变宽，① ⑥ ⑦ ⑧ 各加一块。

### ① 描述角色：加「性格与口味」卡

- 五个特质滑块（01 §2），默认 50；「帮我完善」时 LLM 按描述给出建议值（「懒洋洋但很黏人」→ 活泼 25、黏人 80）并写一句理由，用户可改。
- 物种大类（`species`）单选：人形 / 四足 / 会飞 / 软体 / 其他。影响物理默认值（01 §4）和后面模板的措辞（四足的「攀爬」是「爪子扒着墙」）。
- 口味：从内置食物里勾喜欢 / 讨厌（01 §5）；LLM 完善时从 `persona.likes` 里匹配。
- 写进工程的 `profile`，⑧ 导出时进 `pet.json`。

### ③ 关键帧：站姿 + 选装姿态

站姿（必需）和现在一样。下面多一个「其他姿态」区，每个是一张可选的关键帧，**勾了才生成**：

| 关键帧 | 姿态 | 解锁的动作 | 生成方式 | 对齐 |
|---|---|---|---|---|
| 侧身（已有，分段走路） | `ground` | 分段 move | 图片编辑：站姿 → 侧身 | `feetY` |
| **贴墙** | `wall` | 贴墙待机、攀爬、上墙 / 下墙、松手 | 图片编辑：站姿 → 「侧身贴在画面左侧一道竖直墙面上，双手双脚抓住墙，身体竖直，脸朝左（朝墙）略偏向观众」 | 角色最左侧贴「虚拟墙线」x = 画布宽 × 22% |
| **坐** | `sit` | 坐下 / 起身、坐着待机 | 图片编辑：站姿 → 原地坐下 | `feetY`（屁股着地） |
| **睡** | `lie` | 入睡 / 醒来、睡着循环 | 图片编辑：坐 / 站 → 趴着或蜷着睡 | `feetY` |
| 倒挂（以后） | `ceiling` | | 站姿垂直翻转作为参考 + 编辑 | 顶部 y = 画布高 × 12% |

- 贴墙关键帧 **不能画出墙**（画了就抠不掉）。提示词里只说「贴在左边的竖直平面上，平面是看不见的、和背景同色」，
  生成后自动检查：角色最左侧的不透明像素要形成一条近似竖直的边（手和脚的最左点 x 相差 < 身宽 8%），不过关提示重做。
- 合成首尾帧时，贴墙关键帧 **水平方向不居中**，而是让角色左缘落在画布 22% 处（给攀爬时手往外伸留余量），竖直方向居中。
- 每张关键帧和站姿一样生成 2 张候选、自动检查、用户选。
- 关键帧之间的 **一致性**：都以站姿（不是设定图）为参考做图片编辑，比从设定图分别生成更像同一个角色。

### ④ 规划动作：按姿态分组

> 2026-11-05 追加（L13）：「地面常用」（吃东西、饿了、打哈欠、晕乎乎、下落、落地）和「墙组」（贴墙待机、攀爬、上墙、下墙、松手）
> 在工作台里改为必需，进了基础套装；贴墙关键帧因此也必需。只管工作台（确认规划、导出），程序加载角色包仍只要求原来的五类。
> 老工程打开后 ④ 提示缺哪些，点「补上必需动作」一键加上；⑤「生成还缺的」只生成没有视频的动作。

动作列表按姿态分组折叠，组的标题上显示「这个姿态可用了吗」（01 §3.2 的可用条件：有 idle、有进出的路）：

```
▾ 地面（站姿）                                              ✓ 可用
    待机呼吸 · 被拎起 · 开心挥手 · 小跑 · 东张西望 · …（现有基础套装）
    + 吃东西  + 饿了  + 打哈欠  + 晕乎乎  + 下落  + 落地         ← 新模板，默认勾选「吃东西」「下落」
▾ 墙（贴墙）                                         ⚠ 缺「上墙」，暂不可用
    贴墙待机 ✓   攀爬 ✓   上墙 ☐   下墙 ☐   松手 ☐
▸ 坐（未生成关键帧）
▸ 睡（未生成关键帧）
```

新模板（时间轴写法和现有模板一致，`{}` 由工程填）：

| 模板 | 姿态 / 过渡 | 角色 | 首帧 → 尾帧 | 默认时长 | 要点 |
|---|---|---|---|---|---|
| 吃东西 | ground | `eat` | 站姿 → 站姿 | 8s | 双手捧着一个 **通用小碗**（不画具体食物），低头吃几口、满足地眯眼，碗在结束前消失 |
| 饿了 | ground | `hungry` | 站姿 → 站姿 | 6s | 摸摸肚子、肚子瘪下去再恢复、可怜巴巴看向观众 |
| 打哈欠 | ground | `yawn` | 站姿 → 站姿 | 6s | 张大嘴打哈欠、揉眼睛 |
| 晕乎乎 | ground | `dizzy` | 站姿 → 站姿 | 6s | 摇摇晃晃，头顶转圈的星星（不透明实心卡通样式，结束前消失） |
| 下落 | air | `fall` | 站姿 → 站姿 | 4s | 手脚张开、惊慌挣扎；**原地**，不在画面里下落；无缝循环 |
| 落地 | ground | `land` | 站姿 → 站姿 | 3s | 膝盖弯曲缓冲再站直；原地 |
| 扑 | ground | `pounce` | 站姿 → 站姿 | 4s | 原地向前一扑再回来（逗玩用） |
| 贴墙待机 | wall | `idle` | 贴墙 → 贴墙 | 8s | 抓着墙轻微呼吸、回头看观众；手脚位置不变 |
| 攀爬 | wall | `climb` | 贴墙 → 贴墙 | 6s | 手脚交替向上攀爬的动作，**身体整体不在画面里上移**，一个完整的手脚循环 |
| 上墙 | ground→wall | `wall-enter` | 站姿 → 贴墙 | 4s | 走近左边、跳起、扒住墙；首尾帧不同 |
| 下墙 | wall→ground | `wall-exit` | 贴墙 → 站姿 | 4s | 松开墙轻轻跳下、落地站好 |
| 松手 | wall→air | `let-go` | 贴墙 → 贴墙 | 3s | 手一滑「哇」地松开（之后由物理接管下落） |
| 坐下 / 起身 | ground↔sit | `sit-enter` / `sit-exit` | 站姿 ↔ 坐 | 4s | |
| 坐着待机 | sit | `idle` | 坐 → 坐 | 8s | |
| 入睡 / 睡着 / 醒来 | sit→lie / lie / lie→ground | `sleep` | 坐 → 睡 / 睡 → 睡 / 睡 → 站姿 | 6 + 8 + 6s | 原第五期的「打瞌睡」，挂到姿态图上 |

- **墙相关的公共前缀** 和地面的不一样：把「站在纯色背景前」换成「贴在画面左侧一道看不见的竖直墙面上」，并加一条
  「手脚与墙的接触点始终在同一竖线上，不离开墙面」。四足 / 会飞的物种按 `species` 换措辞。
- **过渡动作**（首尾帧不同）用 D7 方案 C：Seedance 首尾帧模式分别传两张关键帧。模板里写清楚「角色从首帧姿势过渡到尾帧姿势，位移尽量小」，窗口位移由程序插值（04 §5.2）。
- 费用估算按组显示小计；推荐路径：地面组的「吃东西 + 下落」先做（喂食和甩是最常用的新互动），墙组整组一起做（缺一个就不可用）。
- 「这个姿态可用了吗」的判定和加载时用同一段 Core 代码（`StanceGraph.Validate`），工作台和运行时结论一致。

### ⑥ 处理与质检：测量接触点

处理管线（pet-studio/06）每段已经有 alpha，顺手测：

| 测量 | 方法 | 写到哪 |
|---|---|---|
| `body.bounds` / `feetY` | 站姿 idle 第一帧的不透明包围盒；`feetY` 取底边 | `profile.body` |
| `body.mouth` | 不调视觉模型（不值这个钱）：默认取包围盒顶部往下 28%、水平中心偏左 15%（朝左），⑦ 里可以拖一个点改 | `profile.body.mouth` |
| `wall.contactX` | 贴墙待机每帧的最左不透明列（按行取最小 x 再取 10% 分位），全片段中位数 | `profile.body.wall` |
| 攀爬步态 | 和走路步态同一个方法（pet-studio/06 §2.4），换成手部区域、`axis = y` | 动作的 `gait` |
| 过渡位移 | 首帧和尾帧的对齐点差 | 不存，运行时按关键帧算 |

新增质检项：

- **贴墙稳定**：贴墙姿态的片段里，接触列逐帧的标准差 < 身宽 3%，否则「手脚离开了墙，挂在墙上会飘」，建议重做。
- **原地**：下落、攀爬片段的包围盒中心逐帧漂移 < 身高 5%（角色在画面里自己移动了，会和窗口位移叠加）。
- **首尾一致**：过渡动作的首帧要和源姿态关键帧一致、尾帧和目标姿态一致（现有「首尾一致」检查改成按两张关键帧比）。

### ⑦ 试玩：新的试玩开关

试玩窗口（临时打包换到桌面上）加几个按钮，不用等随机链：

- 「去爬墙」（走到最近的墙并上墙）、「掉下来」、「甩一下」（给一个固定初速度）、「喂一个饭团」、「哄睡」
- 状态面板可以手动拉数值（饿 / 困 / 心情），看对应的反应
- 拖一个点调 `body.mouth`；滑块调攀爬步幅、`contactX` 微调（±10 像素）

试玩期间的数值变化不写进真实存档（用临时 `petKey`）。

### ⑧ 导出

- `pet.json` 写 `profile`（01）、动作的 `stance` / `transition` / `anchor` / `gait.axis` / `unlock`（04 §3.2、02 §5）。
- **用到了这些新字段就把 `minAppVersion` 设成支持它们的版本**：旧版程序不认识 `stance`，会把攀爬动作当地面动作播（还会出现在 Agent 的 `play_action` 里），所以必须挡住。
  只有 `profile`（旧版忽略无害）不需要提高。
- 导出前用 `StanceGraph.Validate` 检查：不可用的姿态整组不导出（提示用户），不让坏包出门。
- 源文件（`source/`）多带各姿态的关键帧，以后「以此为基础新建」能继续补动作。

## 2. 给已有宠物补动作

内置的小t、大肥鱼，以及别人做的格式 2 包，都没有新姿态。补的路径：

1. 控制台「动作」页「添加动作 ▾ → 在工作台中生成」（pet-studio/01 §4.3 第 3 条）现在只能加地面动作。扩展成：选姿态 → 没有这个姿态的关键帧时先在工作台里生成（以包的 `source/first_frame.png` 或用户上传的站姿为参考）。
2. 生成的片段进用户覆盖层（`clips/<动作 id>/`），动作定义带 `stance` / `transition`，和包里的动作合并后再算姿态图。
3. 内置角色由我们用工作台生成后直接放进包里（07 路线 P3），作为工作台新模板的第一批验收样本。

## 3. 工程模型的改动（Core/Studio）

- `StudioProject` 加 `Profile`、`Keyframes`（字典：姿态 → 选中的关键帧候选），`PlannedAction` 加 `Stance`、`Transition`（from/to）。
- `ActionTemplate` 加 `Stance`、`Transition`、`Prefix`（用哪套公共前缀），模板表按姿态分组。
- 步骤状态的过期判定：某个姿态的关键帧改了，只让 **用到这个关键帧** 的动作过期（现在是站姿一改全部过期）。
- 生成请求：首尾帧不同时 `first_frame` / `last_frame` 分别取过渡两端的关键帧合成图（05 的方舟视频任务协议已支持）。
